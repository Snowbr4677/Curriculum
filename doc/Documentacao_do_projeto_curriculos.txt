1. OBJETIVO DO PROJETO

Este projeto apresenta uma página pública para consultar os currículos de estudantes
da Escola Dona Zalina Rolim. O objetivo é reunir nome, foto, descrição profissional,
formação, cursos, experiências e dados de contato em uma experiência simples,
organizada e acessível pelo navegador.

O sistema foi desenvolvido como uma aplicação web, utilizando Laravel para rotas,
controladores e renderização das páginas, Blade para a montagem das views, Tailwind
CSS e CSS próprio para o layout, Vite para os recursos frontend e DomPDF para gerar
os currículos em PDF.

O foco desta versão é o portfólio dos alunos. Recursos administrativos existentes
no projeto base não aparecem na navegação pública e não são necessários para esta
apresentação.

5. FLUXO PRINCIPAL DA APLICAÇÃO

1. O usuário abre a página inicial.
2. A página inicial apresenta o nome da escola, a imagem principal e o botão
   "Conhecer os alunos".
3. O usuário entra na página Quem Somos.
4. A página mostra seis cards, um para cada estudante.
5. Cada card possui nome, foto, resumo e área de interesse destacada ao passar o
   mouse ou ao usar o teclado.
6. Ao clicar na foto ou no nome do estudante, o sistema abre o currículo completo.
7. O currículo apresenta cabeçalho da escola, foto, dados pessoais ou de contato,
   objetivo, formação, cursos e experiências.
8. O botão "Salvar currículo em PDF" abre a versão em PDF em nova aba.
9. O botão "Voltar" permite retornar à página anterior.

8. DECISÕES DE INTERFACE

A página inicial foi simplificada para uma apresentação pública direta.

A página Quem Somos utiliza um cabeçalho escuro fixo no topo, a identidade visual
da escola e cards organizados em duas colunas no computador e uma coluna no celular.

Os nomes dos alunos usam negrito e uma linha verde como separador. As fotos ficam
em círculos próprios e não vazam das bordas dos cards.

Ao passar o mouse ou obter foco pelo teclado, o card mostra uma breve informação
adicional sobre área de interesse ou idiomas.

Os currículos usam fundo amarelo claro inspirado na identidade original do projeto,
com uma folha central clara para facilitar a leitura e um cabeçalho escuro com o nome
da escola.

O botão de PDF utiliza uma cor verde e uma descrição completa. O botão Voltar usa
fundo branco, borda discreta e seta para indicar a ação.

11. PERGUNTAS QUE PODEM SURGIR NA APRESENTAÇÃO

Por que Laravel?
Porque separa rotas, controladores e páginas, facilita manutenção e permite usar
Blade sem duplicar a estrutura inteira em cada página.

Por que Blade?
Porque permite reaproveitar HTML, configurar textos por aplicação e integrar dados
diretamente às views.

Por que DomPDF?
Porque gera uma versão em PDF a partir do mesmo currículo exibido no navegador,
reduzindo duplicação de layout.

Como os currículos são encontrados?
O navegador chama uma rota pública com o nome do estudante. O controlador valida
esse nome e retorna apenas uma das views cadastradas.

Como as fotos são carregadas?
As fotos ficam em public/imgs/sistema/alunos e são referenciadas pelas views com
asset(), que gera o endereço público correspondente.

Como o projeto funciona no celular?
As grades mudam de duas colunas para uma coluna por meio das regras CSS responsivas.

Como o projeto evita páginas indevidas?
Uma lista fechada de nomes válidos é usada no controlador de currículo e no
controlador de PDF.

16. CONCLUSÃO

O projeto apresenta uma solução simples para centralizar currículos de estudantes
em uma interface web organizada. A navegação começa na página inicial, passa pela
lista de estudantes e termina em um currículo individual que pode ser salvo em PDF.

A versão atual já possui identidade visual própria, conteúdo organizado,
responsividade básica, navegação clara e separação dos currículos em arquivos
Blade. Os próximos avanços devem priorizar dados reais, validação de informações,
testes automáticos e aprimoramento da geração de PDF.
